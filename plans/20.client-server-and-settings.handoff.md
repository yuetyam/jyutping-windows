Updated on 2026-11-20. This handoff records the opt-in client-server preview, the verification performed on Windows 11 ARM64, and the remaining work before production cutover. [Roadmap](20.client-server-and-settings.md)

## Settings Release startup and memory transfers

Both staged Release executables previously failed with `0xC000027B` on Windows 11 ARM64. The direct ARM64 Release build opened successfully. The publish output was missing the project's generated `JyutpingSettings.pri` and `App.xbf`. The project now includes both in `dotnet publish`, and installer staging and CI check for them. Staged native ARM64 and emulated x64 Settings passed UI Automation after this change. Native x64 startup still needs verification. [Project](../JyutpingSettings/JyutpingSettings.csproj) · [Packaging](../packaging/Build-Installers.ps1) · [CI](../.github/workflows/build.yml)

Run the staged x64 Settings smoke test from the repository root as follows. The script starts a listener with a temporary registry key, launches the settings window, and cleans up its own processes and key. Substitute `ARM64` for `x64` to test the native ARM64 build.

```powershell
pwsh -File backend/tests/Test-SettingsWindow.ps1 -SettingsPath packaging/stage/BackendPreview/x64/Settings/JyutpingSettings.exe -ServerPath backend/target/debug/JyutpingServer.exe
```

The Settings window uses `AppInstance.FindOrRegisterForKey` to redirect repeated launches, a MIDL-generated native bridge, and a serialized worker for settings RPC. Both Windows App SDK 1.8.260921001 and .NET 10 are self-contained. Local builds used .NET SDK 11.0.100. Memory operation results remain visible until dismissed or replaced by another operation. The settings refresh updates the connection warning independently. [Settings window](../JyutpingSettings/SettingsWindow.cs)

## Preview implementation

- The Rust core ports the Windows QWERTY Jyutping engine, Pinyin, Cangjie and Quick, stroke, structure, supplementary text, emoji and symbols, and character-standard conversion. The server uses Windows `winsqlite3` and the existing generated dictionary. The Swift desktop reference is `apple-jyutping@01d20107753929189d758016a5ef0c86aa6a6789`. [Backend notes](../backend/README.md)
- Protocol version 2 adds normal and reverse candidate lists, settings, and memory mutations to local RPC. A preview request carries up to 12 query keys and returns up to 16 candidates. The reply carries reading marks, original lexicon text, display text, consumed key counts, and a memory generation. The version 1 exact-spell operation remains available. [Protocol](../Shared/Protocol/README.md)
- The TSF DLL applies replies in revision-checked edit sessions. It supports deferred Space and candidate-number selection, partial consumption, reverse input, local fallback, and desktop launch recovery on the worker. Learning and forgetting use the original lexicon and avoid replaying uncertain writes. Out-of-range requests and unavailable listeners can use the existing in-process engine. [TSF worker](../Jyutping/IpcProbe.cpp) · [Composition](../Jyutping/CompositionProcessorEngine.cpp)
- The Rust memory store preserves `memory2608` and migrates `core_memory` transactionally. Clear and import increment a durable generation that rejects queued writes from before the operation. Backups use the macOS version 1 portable SQLite format. The WinUI picker launches a separate backend process for file transfer and can signal cancellation through its standard input. [Memory](../backend/server/src/memory.rs) · [Transfer](../backend/server/src/memory_transfer.rs)
- The settings server writes validated individual fields to the existing Windows preferences key and returns server-instance-scoped revisions. Opt-in TSF clients poll once per second, publish changes for older clients through the TSF compartments, and preserve live session input mode. The WinUI app has General, Appearance, Reverse Lookup, Tones, Fonts, Input Memory, Hotkeys, and About pages. It has a backend candidate preview, memory controls, and a manual update command. Cantonese and Hong Kong written Chinese use distinct translations. [Settings persistence](../backend/server/src/settings.rs) · [Settings UI](../JyutpingSettings/SettingsWindow.cs)
- `packaging/Build-Installers.ps1 -BackendPreview` keeps preview DLL builds, staging, and installer output in separate directories. It packages x64 and ARM64 native servers and settings apps, the existing TSF and updater payloads, app-local Visual C++ runtime files, and runtime notices. It adds a Start menu shortcut, a conditional language-bar command, sign-in startup, and a current-session backend stop command for upgrades and uninstall. ARM64X compiles ARM64 and x64-generated MIDL stubs for its respective halves. The default build and installer use the existing in-process path. [Packaging](../packaging/README.md#client-server-preview) · [CI definition](../.github/workflows/build.yml)
